# exocmd__CreationGate — правило допуска нового эффорта

Правило допуска: в vault, где смонтирован ассет правила, новый экземпляр охраняемого класса создаётся, только если он проходит по улике отгруженного либо его цепочка родителей ведёт к якорю, связанному с направлением в разрешённом статусе.

- **Кто исполняет:** движок (`exocortex-core`) у точки записи нового файла — `create`, `create-batch`, `apply` (create-instance и сервисы создания), плагин Obsidian. Синк (`exosync`) правилом не судится: он доставляет, а не создаёт.
- **Один экземпляр = одно правило.** Несколько действующих правил — конъюнкция.
- **Не действует**, если у ассета правила есть `exo__Asset_deprecatedBy` или `exo__Asset_archived: true`.
- **Отказ громкий:** код 4, префикс `CREATION_GATE_REFUSED:`, имя правила (`exo__Asset_label`), причина и текст «как правильно» (`exo__Asset_description`); ничего не записывается.
- **Сломанное правило — fail-closed там, где известна его область:** без `guardedClass` отказ любому созданию, кроме нового ассета правила; без полей цепочки — отказ охраняемым кандидатам без улики.
- Суперкласс — `exocmd__DeclarativeRule`; соседи — `Precondition`, `PropertyDefault`, `InheritanceRule`.
