# Re-anchor isDefinedBy to the picked ontology

Step 1 of the «Set Ontology» composite — the **generic** counterpart of
[[af5090bf-304f-4670-acd5-ab5a42f76bd8|Re-anchor isDefinedBy to archive ontology]]
(Archive Ontologically, RFC 78c2b7d0 C5): where that step computes the target
ontology from a NamedQuery (`targetValueQuery`, archive-specific), this one takes
it from the **user's pick** in the composite's `assetRef` form field.

- `exocmd__Grounding_type` = `property_set`
- `exocmd__Grounding_targetProperty` = `exo__Asset_isDefinedBy`
- `exocmd__Grounding_targetValueRef` = `$input.ontology`

⛤ **Why `targetValueRef`** (since 2026-09-26, req `ea4f8efa`): the `targetValueRef`
branch of `GroundingExecutor.executePropertySet` normalises its input through
`extractAssetReference` (req `b06129dc`). A bare uid, `[[uid]]`, `[[uid|alias]]` and
the picker's quoted `"[[uid]]"` all become one `"[[<uid>]]"`, so the value is written
as a reference and the graph gets the asset → ontology edge whichever surface supplied
it (plugin `ReferencePicker` or CLI `--input`).

⛔ **Retracted — the former note «Why `targetValueSubstitution`, not `targetValueRef`».**
It said `targetValueRef` wraps the value itself, so the picker's quoted form would come
out as `"[["[[uid]]"]]"`. That described the engine BEFORE req `b06129dc`; the wrap is
now idempotent. The verbatim contract it chose had its own hole: a bare uid was stored
as a **literal** (no graph edge, the command still reported success), and an unquoted
`[[uid]]` is refused (req `29e0d1b6`). The regression axis is
`packages/cli/tests/integration/set-ontology-reference-ea4f8efa.integration.test.ts`
in `kitelev/exocortex`: moving this step back to `targetValueSubstitution` turns O1, O2
and O4 red (mutant M1).

Must run **before** the folder-relocation step so `repairFolder` sees the new
`isDefinedBy` (same load-bearing ordering as the archive composite).
