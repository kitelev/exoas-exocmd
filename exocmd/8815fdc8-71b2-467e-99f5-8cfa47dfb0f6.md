# Allow transition to Backlog (from Draft / Cancelled / Waiting)

SPARQL ASK precondition: returns `true` only when current status ∈ {Draft, Cancelled, Waiting}.

State-machine forward transition: Draft → Backlog is the standard onboarding path; Cancelled → Backlog allows resurrecting a cancelled asset back into the workflow. From any other status, use Rollback Status (one step back).

**Waiting → Backlog добавлен 2026-08-13** (задача `ceae3805-564b-4dc1-a95b-9ebfeace3194`) — это **un-park**: обратный ход команды «Park — Waiting» (`park-waiting`, `1afadafc`). Отдельной un-park-команды намеренно нет: «Move to Backlog» уже означает «вернуть в очередь», и она привязана ровно к тем же классам (Task / Project / Action), что и park.

⛔ Правка внесена `Edit`-ом через audited-окно (`~/.claude/.dogfood-cli-fallback`), а НЕ `set-property`: значение — YAML folded block-scalar (`>`), который `set-property`/`remove-property` ломают line-based заменой и при этом рапортуют успех (rules/vault-asset-creation §block-scalar).

Used by "Set Status Backlog" command.
