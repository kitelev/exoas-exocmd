# Set Ontology → Asset binding

Binds the «Set Ontology» command (`b3998813`) to all `exo__Asset` instances —
inline, `maintenance` group, order **215**: immediately after «Repair Folder»
(`210`), its closest sibling (both are about the asset↔ontology↔folder
relationship), and before «Rename to UID» (`220`).

`targetClass: exo__Asset` is the broadest scope, mirroring the «Repair Folder»,
«Clean Properties» and «Archive Ontologically» siblings: re-anchoring is a
maintenance operation that is meaningful on any asset, so there is nothing to
gate on and the command carries **no precondition**.

⛤ A command without a binding is silently dead in the UI — `resolveForAssetMulti`
never surfaces it and the inline button never renders, even though
`apply set-ontology` (cliName → `loadCommand`, binding-free) works. That exact
orphan-command bug hit «Archive Ontologically» (see the note in `0fa306a8`) and
«Archive Completed» (`58548853`) before it; this binding is created together with
the command precisely so it cannot recur here.
