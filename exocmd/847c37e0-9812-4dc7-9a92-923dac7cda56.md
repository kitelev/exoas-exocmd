# Target is not a prototype

SPARQL ASK precondition: returns `true` when the target asset is **not** a
prototype-template — i.e. none of its `exo__Instance_class` values has a class
chain that reaches `exo__Prototype` (`ems__TaskPrototype`, `ems__ProjectPrototype`,
`ems__EffortPrototype`, any user-defined prototype subclass, `exo__Prototype`
itself, etc.).

**Native `exo:Class_superClass*` walk (de-hacked from the STRENDS suffix
workaround, req 5579ffa1 + resolver req 9fddda62):** the clause is
`FILTER NOT EXISTS { $target exo:Instance_class ?c . ?c exo:Class_superClass* exo:Prototype }`.
Historically this transitive walk did NOT resolve on the real store — a class's
`exo__Instance_class` object is the *symbolic* class IRI
(`https://exocortex.my/ontology/ems#TaskPrototype`) while `exo:Class_superClass`
triples live on the class *file* IRI, and SPARQL could not bridge the two → the
gate never fired (the interim `STRENDS(…, "Prototype")` name-suffix check was
used instead). The query-time class-hierarchy resolver
(`ClassHierarchyResolvingStore`, req 9fddda62, default ON) now heals that seam at
match-time, so the semantic walk resolves for symbolic-form instances with zero
store growth. The walk catches every prototype class **by its class chain**,
independent of the `…Prototype` naming convention (e.g. a user-created
`ems__TaskPrototype` subclass labelled in Russian).

Used to hide instance-lifecycle commands (Start / Mark Done / Set Criticality /
status transitions / child-creation / convert / vote) from prototype-template
assets while leaving universal-maintenance (`targetClass exo__Asset`) and the
prototype's own create-instance command untouched.

Realises requirement `5579ffa1-a829-4fcf-b93d-4fb664b02d62` (design node
`f853eadd-6132-43f8-84ba-25a75641096a`). The same `FILTER NOT EXISTS { … }`
clause is conjoined into the 17 existing lifecycle status/criticality/convert
preconditions so the not-a-prototype gate ANDs with their status gates.
