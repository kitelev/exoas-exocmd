# Create Action

Dynamic command that creates a new atomic `ems__Action` asset under the target.
Sibling of "Create Task" (`dec97198`) — works analogously.

- **Grounding**: `1bc1e938` (`create_instance`, targetClass `ems__Action`).
- **Precondition**: `365095bc` "Not a prototype, not archived, and visible until
  terminal" — the button shows on real instances (Project, Task) and is hidden on
  prototype templates, archived assets and terminal-status efforts.
- **Icon**: zap (Lucide).
- **Category**: creation.
- **Bound to**: `ems__Project` (`922ecc10`) and `ems__Task` (`655526c7`).

## What the created Action inherits

See `1bc1e938` for the full table. In short: a `ems__Project` target becomes the
new Action's `ems__Effort_parent` (universal rule `01f570c9`), and since
2026-09-09 so does an `ems__Task` target (universal rule `65acce2f`); an
`ems__Area` target lands in `ems__Effort_area` instead (grounding rule
`3f08f5a8`). Prototype targets get neither, by design — and the precondition
refuses them outright.

⚠ Before 2026-09-09 this command silently produced a parent-less Action when
invoked on a Task — neither the grounding nor the Universal Template carried a
Task-conditioned parent rule. Fixed
under GitHub issue `kitelev/exocortex#4220` (vault task
`0e914ac3-64bd-4e13-896a-d64b3a3e8d30`). Two earlier statements in this body were
also inaccurate and have been corrected: the precondition is `365095bc`, not
`847c37e0` (which is the narrower "Target is not a prototype"), and the epic
reference `40188c71` no longer resolves in any mounted assetspace, so it is
dropped.
