# InheritanceRule: no ems__Effort_parent for a trash reason

Attached to the step «Create trash reason» (`[[a960eb76-c669-43af-80b4-94dac438dd70]]`, req `088f94c6`). Its job is to switch OFF, for that one step, the two Universal Default Template rules that write `ems__Effort_parent`:

- `[[01f570c9-3bf2-4ec8-af27-0aa4d9cbc29f]]` — target is an `ems__Project`
- `[[65acce2f-e0eb-48e2-bcb3-8d5c9664e799]]` — target is an `ems__Task`

Both look at the class of the CLICKED asset, not of the asset being created. Without this rule, trashing a task or a project would make the new reason a child effort of it (`ems__Effort_parent`), although a reason is not an effort (domain of `ems__Effort_parent` is `ems__Effort`).

Mechanism: `mergeInheritanceRules` (`UniversalDefaultTemplateResolver.ts`) lets a grounding's own rule for a property replace every universal rule for that property (documented in `[[62907ff4-bf91-4c94-8e02-92b3ca2bc798]]`). This rule's condition is `ems__EffortTrashReason` — `trash` is bound to tasks, projects and actions only, so the condition never matches and the rule itself writes nothing.

The reason still links to the effort through `exo__Asset_relates` (`[[c296790a-7987-4acb-a43e-72cccb9242d9]]`).
