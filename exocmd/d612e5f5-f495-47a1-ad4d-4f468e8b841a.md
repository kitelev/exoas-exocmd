# Trash effort (composite)

Composite grounding for the Trash command (terminal state + resolution timestamp + a reason recorded as its own asset):

0. Create the reason — `[[a960eb76-c669-43af-80b4-94dac438dd70]]` makes a new `ems__EffortTrashReason` asset in the effort's folder and ontology, labelled with the required input `label` and linked to the effort via `exo__Asset_relates`. It runs first, so a failed create aborts the command before the effort changes.
1. Set `ems__Effort_status` → `[[5d14f18d-db2b-4847-9ac1-144cb93b2541]]` (Trashed)
2. Set `ems__Effort_trashedReason` → `[[6332c6d8-861f-475c-a051-4b6bbb669f7a]]` (Неактуально / осознанный отказ — deliberate-drop default)
3. Set `ems__Effort_resolutionTimestamp` → current local timestamp
4. Bump `exo__Asset_updatedAt`

Atomic via `GroundingExecutor.executeComposite` rollback on step failure. Used by command `Trash` (`0c3debe0`).

The effort body is never rewritten (req `088f94c6`, ems__Bug `b090c2e8`): the previous fourth step «Add Trashed Comment» (`d3412530`, a private `body_template` step in exoas-my) replaced the whole body with an empty «## Trash Reason» stub and was removed.

Note: 2026-06-28 `Cancelled` status was collapsed into `ems__Effort_trashedReason` — single terminal «not-Done» status is `Trashed`, with reason capturing *why* (started-not-finished vs no-longer-relevant). Resolution-timestamp semantics preserved.
